# 대화형 관심 범위 구체화

AI는 먼저 사용자의 표현을 이해하고 직접 맞는 일·인접한 일·탐색할 일을 나눠 제안합니다. 정해진 진로로 유도하지 않으며 제안 이유와 차이를 설명하고 선택을 돕습니다. 사용자가 원하면 제한 없이 탐색부터 시작할 수 있습니다.

가상 예시: “매장 운영을 개선하는 일을 찾고 싶다” → AI가 현장 운영, 재고·공급망 관리, 고객 경험 개선 등의 업무 차이를 설명 → “현장 문제를 직접 해결하는 일과 데이터를 정리해 개선안을 만드는 일 중 어느 쪽이 더 끌리나요?” → 답을 바탕으로 다음 질문·검색어를 구체화합니다.

다른 가상 예시: “여행 서비스 기획”이면 예약 경험 설계, 상품 운영, 고객 지원·서비스 개선의 차이를 설명합니다. 예시의 기술·학력·지역을 사용자에게 적용하지 않습니다.

## 저장 형식

`profile.example.json`은 비어 있는 초안입니다. MCP save_search_profile에 같은 필드를 전달해 로컬 profile.json에 저장합니다. 사용자가 원하면 파일을 직접 수정할 수도 있습니다.

- state: draft 또는 confirmed. 미확정 상태에서는 자동 검색 계획을 만들지 않습니다.
- user_intent: 사용자의 원래 관심을 요약합니다.
- roles / industries: 받아들인 직무·산업.
- skills / education_keywords: 사용자가 강조하고 싶은 기술·학력 키워드. 근거 없는 능력을 추가하지 않습니다.
- experience: unknown / entry / experienced / any.
- locations / must_have / exclude_keywords: 위치·필수조건·제외 조건. 검색만으로 충족을 보장하지 않으며 원문에서 검토합니다.
- search_terms: 사용자가 포함하기로 한 동의어·세부 검색어.
- proposed_expansions: AI가 제안했으나 아직 받아들이지 않은 방향. 검색·점수화에서 제외합니다.
- days: 최근 기간, 기본 30일.

확정은 역할/산업 중 하나 이상이 있어야 합니다. 한 필드 최대 20개, 항목당 최대 80자입니다. 생성 질의는 역할×산업과 확정 세부 검색어를 합쳐 최대 24개이며 잘린 경우 표시합니다. 하루 호출 예산과 기간 누락 가능성을 고려해 범위를 나눠 실행하세요. 프로필 파일은 소유자 권한 0600으로 저장하고 Git에서 제외합니다. 실제 검색에 사용한 질의는 선택한 검색 공급자에 전달됩니다.

질문은 매번 1–3개로 제한하고 가장 큰 불확실성을 먼저 해결합니다. 기존 대화/프로필에 있는 답을 재질문하지 않습니다. 결과가 적거나 부정확하면 어떤 범위를 넓히거나 좁힐지 구체적 선택지를 제시하고 사용자 답을 반영합니다. 스킬이 질문·추론을 수행하고 MCP는 저장·질의 생성·수집을 담당합니다.
